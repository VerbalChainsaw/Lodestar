# Lodestar v0.7 Payload and Payback Codeplan

## Product decision

Every Lodestar change must satisfy four conjunctive gates:

1. stay fast;
2. stay out of the way;
3. provide measurable lift; and
4. return more value than its complete operational cost.

The current engine passes deterministic correctness, isolation, inspection, and
runtime gates, but a real 71-project startup packet reaches 16,300 bytes and the
live-agent/economic claim is not yet proven. This work closes those gaps without
adding a service, daemon, dependency, background scan, telemetry, or read-path
write.

## Scope

### Compact startup routing

- Reduce the hard `start` response ceiling from 16 KiB to 5 KiB.
- Keep required records complete.
- Represent optional records as compact routing cards containing only identity,
  type, priority, summary, and links.
- Retain deterministic ordering, explicit omitted IDs, locator warnings, exact
  retrieval, project isolation, and fail-closed required-context behavior.
- Add the measured startup packet size and budget to the paired benchmark.

### Visible package transitions

- Make installer preflight inspect the currently installed package using a
  read-only npm-root query.
- Report the installed version, target version, and transition as `install`,
  `upgrade`, `reinstall`, `downgrade`, or `replace-unknown`.
- Refuse an accidental downgrade or unrecognized-version replacement unless
  `--allow-downgrade` is explicit.
- Include the running package version in `doctor` output.
- Preserve the existing package backup, rollback, state, adapter, and PATH
  safety behavior.

### Payback evidence

- Report inspected bytes avoided, evidence bytes added, elapsed milliseconds
  saved, and startup-payload bytes without inventing dollar or token claims.
- Re-run deterministic small, standard, stress, operation, and tiny losing
  controls.
- Run the registered live-agent plan only with an explicit trial and cost cap.
  If invocation-scoped publishable credentials are unavailable, retain and
  label the smallest authenticated local smoke run as non-publishable evidence.

## Compatibility and safety

- Store schema, generation identity, indexes, snapshots, and write semantics do
  not change.
- Existing exact `get`, linked `resolve`, and scoped `find` results do not
  change.
- The startup packet remains version 1; optional cards lose inline locator,
  alias, and topic detail because those remain available by exact ID.
- Installer preflight performs read-only subprocess and bounded metadata reads.
- Unknown or malformed installed package metadata fails closed.
- Downgrade intent must be explicit.

## Release gates

- Startup responses are at most 5 KiB and preserve all required records.
- The real canonical project startup packet is at most 5 KiB.
- All deterministic lift gates pass at 10, 100, and 500 projects.
- No hot-path latency materially regresses from v0.6.1.
- Installer transition and rollback tests pass on Linux/WSL and hosted Windows,
  Ubuntu, and macOS.
- Live-agent evidence is labeled according to its authentication/isolation
  quality; no contaminated smoke result becomes a product claim.
- No version tag is published until the deterministic product gates pass and
  the release claim is explicitly bounded to what those gates prove.

## Current evidence

- Real canonical startup: 4,879 bytes, down from 16,300 bytes, with all six
  required records preserved.
- Full local suite: 203/203 passing; package dry-run contains only 74 declared
  public files and zero runtime dependencies.
- All deterministic 10/100/500-project profiles pass. The final release run
  measured median elapsed-time reductions of 35.51%, 34.39%, and 33.62% while
  preserving 4/4 answers, avoiding broad search, and returning zero
  cross-project records.
- At 100 projects, Lodestar avoided 1,023,653 inspected bytes while adding
  3,234 evidence bytes and saving 5.305 ms at the median. At 500 projects it
  avoided 8,274,085 bytes and saved 21.045 ms.
- Bounded-concurrent deep inspection reduced the same retained-history audit
  from 48.87 seconds to 18.74 seconds. Verified recoverable maintenance reduced
  the clean canonical audit to 3.75 seconds with zero issues.
- The active PATH installation was checksum-verified and upgraded from v0.5.0
  to the released v0.6.1 without modifying the Codex adapter.
- The capped local live-agent smoke is correctly labeled non-publishable. Its
  refined pair was correct and inspected one repository file instead of six,
  but added 3.585 seconds and 2,286 reported input tokens.
- Therefore v0.7.0 passes the speed, unobtrusiveness, deterministic lift, and
  measured operational-payback gates for normal and stress-scale repositories.
  The release can ship with that bounded claim. Universal live-agent economic
  payback remains unproven and must not be represented as part of the release.
