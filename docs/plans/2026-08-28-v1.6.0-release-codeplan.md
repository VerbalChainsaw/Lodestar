# Lodestar v1.6.0 release codeplan

Date: 2026-08-28
Scope owner: Director
Method: Codeplan (evidence-gated) + Center Audit (claim proof) + golden rules.
Status: PLAN-OUT (EXEC-OUT appended after verification).

## Task contract

- Required behavior: publish the post-1.5.0 patchwork (six lean/audit commits
  present only on the local branch) as a new revision on GitHub, with release
  notes, a new announcement page, and the additive skill-package update
  (Adderall skill + restored current reference material).
- Acceptance criteria: version bumped consistently across `package.json`,
  `src/version.mjs`, and `codex-plugin/.codex-plugin/plugin.json`; CHANGELOG
  has a released-section entry matching the tag; `docs/releases/v1.6.0.md`
  exists and satisfies the release-metadata test; announcement page + social
  card committed; skill payload updated additively (nothing removed or
  shrunk); full suite, assets parity, pack check, and packed-artifact smoke
  pass; `main` fast-forwarded; tag pushed; release workflow produces npm
  publish + GitHub release.
- Must preserve: the v1.5.0 local tag and its release state (codeplan
  mandate), `.backups/`, historical release/announcement docs, the runtime
  contract (no code changes in this tranche), `release.yml` untouched.
- Out of scope: install/uninstall/data-path hardening (separate tranche),
  `.backups/` cleanup, Lodestar-Ready folder, any code refactor.
- User constraints: skill package update must be additive ("don't make things
  dumber or smaller like we did last time"); approval prompts disabled;
  danger-full-access granted.
- Known constraints: `release.yml` verify step demands tag == package.json
  version, `docs/releases/<tag>.md` present, `## <version> - ` CHANGELOG
  entry, and the tagged commit an ancestor of `origin/main`.

## Candidates

- V1 `1.6.0 via owning pipeline` (fingerprint: `convention-minor`,
  `owning-mechanism`, `fast-forward-main`): bump to 1.6.0 (one minor per
  release is the standing convention since 1.2.0; removal of the documented
  `--startup-budget` option is a semver minor), release notes + announcement
  + social card, ff-push `main` (51eeda9 -> tip, no force), push new tag
  v1.6.0, let `release.yml` publish npm + GitHub release.
- V2 `1.5.1 patch` (fingerprint: `semver-literal`, `patch-bump`): same
  mechanics with 1.5.1. Fails repository convention (every release since
  1.2.0 took a new minor, including small ones like 1.4.2/1.4.3) and
  undersells a documented-option removal.
- V3 `retro 1.5.0` (fingerprint: `tag-repoint`, `retro-release`): push the
  current tip as v1.5.0. Fails contract preservation: CHANGELOG already
  treats 1.5.0 as released, the patchwork is Unreleased content, and the
  standing codeplan mandates "v1.5.0 tag/release state untouched".
- V4 `manual release` (fingerprint: `bypass-pipeline`, `manual-publish`):
  manual `gh release create` + manual npm publish. Fails the owning-
  mechanism gate: duplicates the pipeline, skips CI verification, loses
  provenance attestation.

  release pipeline. Disqualified.
