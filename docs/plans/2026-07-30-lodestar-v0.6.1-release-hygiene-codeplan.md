# Lodestar v0.6.1 Release-Hygiene Codeplan

**Status:** Implemented and locally verified

**Target:** `v0.6.1` patch release from the verified `v0.6.0` commit

**Product boundary:** No context-store behavior or data-format changes

## Objective

Publish a clean patch release that removes stale release-candidate language,
states the supported distribution channel precisely, normalizes npm package
metadata, adds public security guidance and dependency automation, incorporates
fresh benchmark evidence, and leaves the GitHub repository protected against
accidental or unverified release changes.

## Changes

1. Bump package, CLI, and installer versions to `0.6.1`.
2. Replace stale pre-release wording in the README and release-facing
   documentation with verified publication language.
3. Add `docs/releases/v0.6.1.md`, update the changelog, and include the new
   release notes in the package.
4. Normalize `bin` targets so `npm publish --dry-run` does not rewrite package
   metadata.
5. Add `SECURITY.md` and Dependabot configuration for npm and GitHub Actions.
6. Keep distribution honest: the supported public install source is the
   checksum- and provenance-attested GitHub tarball. Public npm publication is
   outside this patch because no npm publishing identity is configured.

## Fresh evidence

- Run the deterministic paired retrieval benchmark with new samples.
- Run the full small, standard, and 500-project performance suite.
- Run the category benchmark dry plan without starting or charging a model.
- Retain neutral or unfavorable timing results; correctness, determinism,
  isolation, and inspected-storage reduction remain the release gates.

## Release gates

- Complete Linux/WSL Node test suite.
- Complete native Windows Node test suite with only intentional platform skips.
- Packed-package help, version, install, doctor, snapshot, restore, maintenance,
  and performance lifecycle.
- `npm publish --dry-run` without metadata-correction warnings.
- Hosted Ubuntu, macOS, Windows, and CodeQL checks on the exact commit and tag.
- Public tarball checksum and SLSA provenance verification.
- Clean worktree with `main`, `origin/main`, and `v0.6.1` resolving to the same
  commit.

## Repository controls

After publication:

- enable vulnerability alerts and Dependabot security updates;
- retain secret scanning and push protection;
- protect `main` with required cross-platform and CodeQL checks, no force push,
  and no deletion;
- protect `v*` tags against deletion and non-fast-forward updates.

Applying protections after the release commit is pushed avoids stranding the
patch behind checks that cannot exist until the commit reaches GitHub.

## Execution result

- Fresh 100-project lift: 4/4 answer parity, no broad search, zero leakage,
  90.63% fewer files, 97.62% fewer inspected bytes, and 33.11% lower median
  elapsed time across 15 samples.
- Full performance suite: 3/3 profiles passed through 500 projects; the stress
  case saved 97.66% of files and 98.63% of inspected bytes.
- Tiny-fixture controls retained two elapsed-time losses while still passing
  the correctness and storage gates, documenting the fixed-cost boundary.
- Category benchmark: deterministic 48-trial plan reproduced without model
  execution or cost.
- Linux/WSL: 201/201 tests passed with no skips.
- Native Windows: 198 tests passed, zero failed, and three intentional
  platform skips.
- The packed `0.6.1` help, version, install, deep-doctor, snapshot, verify,
  restore, restored-doctor, maintenance, and quick-performance lifecycle
  passed.
- `npm publish --dry-run` no longer reports package metadata corrections.

The tag-triggered workflow remains the authority for hosted cross-platform
verification, checksum generation, provenance, and public release creation.
