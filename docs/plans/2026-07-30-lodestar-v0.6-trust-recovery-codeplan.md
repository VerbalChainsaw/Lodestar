# Codeplan: Lodestar v0.6 trustworthy context continuity

## Contract

- Outcome: agents and operators can detect corrupted or stale context, recover
  a verified active generation, and receive deterministic mutation outcomes
  without expanding the normal retrieval path.
- Preserve: `start`, `get`, `resolve`, and `find` behavior and I/O; JSON/JSONL
  canonical state; immutable content-addressed generations; scoped reads;
  repository authority; zero runtime dependencies; and the no-daemon design.
- Release identity: publish as `0.6.0` with new release notes and a new tag.
- Out of scope: automatic destructive purge, a public schema-migration command
  before a real migration exists, mandatory format conversion, databases,
  object stores, watchers, cloud sync, source ingestion, and automatic refresh.

## Candidate decision

Frozen axes: paradigm fit, data safety, user-visible outcome, verifiability,

## Mutation invariants

For every mutation and injected failure:

1. The visible state is either the complete prior state or the complete new
   state.
2. An error before rename means the destination did not change.
3. A directory-sync error after rename is a committed result with explicit
   durability uncertainty, not a false unchanged-state error.
4. Audit failure restores the prior pointer only when the audit replacement
   did not commit.
5. Failed staging removes every known or partially written transaction file.
6. No automatic operation irreversibly deletes quarantined generations.

## Integrity invariants

- A sealed generation manifest must exactly match the regular-file set beneath
  the generation root, excluding the manifest itself.
- Manifest paths are canonical, confined, unique, and slash-normalized.
- Deep doctor recomputes source identity and deterministic index content.
- Integrity detects corruption and inconsistency; it does not claim
  cryptographic authenticity against an attacker able to rewrite the complete
  local state.
- Legacy unsealed generations remain readable and are reported explicitly.

## Product surface

- `doctor --deep`: complete file-set, checksum, source-identity, and semantic
  index verification.
- `snapshot --to` and `snapshot --verify`: portable verified active-generation
  snapshots.
- `restore --from --home <new-path>`: verified restore without overwrite.
- `maintain`: read-only deep inventory, source drift, exact retention plan, and
  audit-rotation plan.
- `maintain --apply`: recoverable quarantine moves and audit rotation after the
  same deep plan; no purge.
- `recover <generation> [--promote]`: deeply validated, audited quarantine
  recovery with rollback if restoration or promotion fails.

## Release gates

- Required-file corruption and manifest omission matrix: 100% detected.
- Fault matrix: partial write, file sync, rename, directory sync, audit write,
  rollback, snapshot copy, and retention move.
- No `.tmp-*`, `.build-*`, or displaced artifacts when cleanup operations are
  available.
- Snapshot restore parity for generation, graph, indexes, and audit prefix.
- Maintenance preview/apply target parity with the active generation retained.
- Resource limits have accepted-maximum and rejected-maximum-plus-one tests;
  project scale is bounded by measured evidence.
- Current retrieval parity remains 4/4 with no broad search or cross-project
  leakage at 500 projects.
- Packed lifecycle commands pass locally and in required hosted Windows,
  Linux, and macOS jobs on the exact release commit.
- The live 71-project store passes deep structural verification; legacy
  generations and stale or unavailable project locators remain explicit
  operator warnings rather than hidden failures.

## Implementation sequence

1. Repair atomic staging cleanup and post-commit durability reporting.
2. Make generation cleanup recursive, bounded, and error-preserving.
3. Enforce manifest-to-filesystem completeness.
4. Align resource limits with measured scale.
5. Remove destructive purge and the premature public migration surface.
6. Make maintenance preview and apply share the same deep retention plan.
7. Add fault, integrity, package-lifecycle, and boundary tests.
8. Bump and align package metadata, changelog, README, release notes, and CI.
9. Run WSL, native Windows, package, 500-project, and live-store gates.

duplicate unhealthy-locator diagnostics. These are the final v0.6 surface
