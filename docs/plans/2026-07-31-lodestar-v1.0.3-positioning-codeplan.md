# Lodestar 1.0.3 front-page positioning codeplan

## Objective

Put the central product conclusion on the GitHub and npm front page:
Lodestar 1.0 is the stronger Lodestar for its stated job because it keeps the
useful engineering qualities of the original while removing machinery that
did not directly help store, retrieve, relate, validate, or migrate context.

The comparison must be explicit without being boastful or dismissive of the
original work.

## Release boundary

- Publish `lodestar-agent-context@1.0.3` because npm versions and their README
  payloads are immutable.
- Change front-page copy, version metadata, release notes, changelog, and the
  version-specific social release asset.
- Do not change commands, schemas, database behavior, migration behavior,
  dependencies, package contents, or executable count.
- Keep the generic hero unchanged.

## Front-page contract

Near the top of `README.md`, say in first person that:

1. the original Lodestar established the useful idea of stable structured
   project context;
2. it also accumulated custom storage, lifecycle, installer, readiness,
   discovery, experiment, and multi-executable machinery;
3. Lodestar 1.0 retains deterministic JSON, explicit schemas, stable IDs,
   bounded behavior, diagnostics, cross-platform support, transactions, and
   honest uncertainty;
4. it replaces the removed machinery with one SQLite database and one CLI;
5. for the product's current stated job, 1.0 is simpler, safer to operate,
   easier to understand, and the recommended version.

Do not claim universal superiority, completeness, accuracy, performance, or
token savings. Do not use provider-specific branding or disparage users of
the old releases.

## Implementation

1. Add a concise comparison section above the existing use-case explanation.
2. Use a small two-column table for exact original-to-1.0 reductions.
3. Bump `package.json` and the CLI version constant to 1.0.3.
4. Add a dated changelog entry and `docs/releases/v1.0.3.md`.
5. Create `docs/assets/lodestar-v1.0.3-social.png` from the existing clean
   background with deterministic local typography and no metadata chunks.

## Verification

- Search the public copy for unsupported readiness, completeness, token, and
  provider-branding claims.
- Run the complete Node 24.15.0 test suite and package dry-run.
- Verify the package still contains exactly one executable and 30 files.
- Run actionlint on all workflows.
- Smoke-test the exact packed artifact without `lodestar init`.
- Require hosted Ubuntu, macOS, Windows, and CodeQL checks on the PR, merged
  main commit, and release tag before publication.
- After publication, verify npm `latest`, registry signature, provenance,
  GitHub assets, checksum, front-page copy, and a clean public install.
