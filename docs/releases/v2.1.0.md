# Lodestar 2.1.0

> **Development checkpoint.** This package version was never published to npm. This note records a local 2.x checkpoint, not an installable public release. See the [2.1.2 release notes](v2.1.2.md) and [current installation guide](../installation.md).

Package: `lodestar-agent-context@2.1.0`.

This release makes the existing installation owner easier to use and closes
measured transport and mutation gaps. Contract 5 and schema 5 remain unchanged.

- Setup discovers standard local launcher destinations. Start returns the maintained
  operating guide, installation status, checked paths, and a scoped repair command.
  Startup remains read-only; authorized setup applies missing or owned updates.
- Complete JSON argument arrays can travel through `--args-file` or `--args-stdin`.
  Native read calls use stdin for arguments. `--output` writes the complete response
  to a new file and returns its byte length and SHA-256 for verification.
- Git Bash translates declared path values while preserving opaque arguments.
  WSL supplies its actual home for startup checks. Managed skill payloads retain
  exact source bytes across Git checkout settings.
- Structured JSON accepts a leading BOM and preserves Unicode and data line endings.
  Duplicate decoded object keys, decimals that would change meaning, and malformed
  UTF-8 are rejected before writes. MCP shares those checks and validates controls.
- Existing admitted transactions and exact-request replay remain the only write
  mechanism. The package adds no daemon, postinstall hook, or independent schema.

Install the supplied tarball, run `setup --apply` for the selected homes, and start
fresh host sessions. Unchanged owned assets upgrade without forced replacement.
Read [installation](../installation.md) for complete-input/output examples and
[limitations](../limitations.md) for the scope of installation checks and native
host dependencies. File health does not establish authenticated model invocation.
