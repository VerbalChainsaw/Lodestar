# Lodestar 2.2.0

Package: `lodestar-agent-context@2.2.0`.

This release hardens the agent-facing surface: failures teach the exact repair,
large reads are captured before a host can clip them, and a rejection register
keeps settled subjects settled. Contract 5 and schema 5 are unchanged; existing
2.x stores need no migration.

## What changed

- **Guided conflict failures.** Contract failures that previously carried only a
  generic action now name the repair: an update missing its `remove` array, a
  decision write with the wrong predecessor or incomplete resolved heads, a
  project binding whose root evidence moved, and a promotion or write targeting
  a non-canonical project scope. The public `put` summary states the update
  `set`/`remove` requirement directly.
- **The rejection register.** Record an approach the project has settled against
  — a model, a data set, an architecture — as a `kind: "rejection"` record with
  a subject, a verdict, and a one-line reason. Current rejections appear in
  orientation (`start`) and in `find`; a direct `put` whose record carries the
  same subject receives a non-blocking advisory in the response `next` field,
  persisted inside the acceptance receipt so an exact retry replays it
  byte-for-byte. Reusing an alias that belongs to a current rejection names the
  owning record. The advisory never refuses a write.
- **Large-read guidance.** The bootstrap instructions, the packaged skill, and
  the knowledge reference now cover large responses as well as clipped ones:
  capture big reads with `--output <new-file>` and read the sections you need.
  No startup budget is reintroduced.
- **Repository verification.** The managed-assets build script documents the
  byte-manifest rule and the required `--source-root` invocation in its docblock.

## Using the register

Complete contract-5 examples ship in the packaged knowledge reference
(`managed-assets/skills/lodestar/references/knowledge.md`, section "Settled
rejections"). Keep one rejection per subject; set `priority` and
`semantics.subject` (`rejection:<slug>`) explicitly; retire through `delete` or
a recorded `lifecycle` update carrying a `retirement_reason`. Current
orientation then omits it while exact history remains.

## Upgrade

```text
npm install --global lodestar-agent-context@2.2.0
lodestar setup --target all
lodestar setup --target all --apply
```

The optional Codex plugin keeps the 2.1.4 packaging rule: the package root is
the plugin root. Custom marketplace entries pointing at `codex-plugin/` must be
updated before reinstalling, and a plugin already cached by Codex needs a fresh
task after updating.

## Compatibility

Requires Node.js 24.15.0 or newer. Contract 5 and schema 5 are unchanged; no new
data migration is required. Release checks run on Windows, Linux, and macOS.
