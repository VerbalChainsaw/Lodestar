# Lodestar 1.1.0

Lodestar 1.1.0 unifies local agent state behind one product: one `lodestar`
executable, one versioned JSON envelope, one universal record model, and one
SQLite database.

The release absorbs session startup, durable knowledge, advisory work presence,
and cross-session handoff without adding a daemon or background service. The
model-facing vocabulary is now consistently `start`, `get`, `find`, `links`,
`put`, `work`, and `handoff`.

![Lodestar 1.1.0](https://raw.githubusercontent.com/VerbalChainsaw/Lodestar/v1.1.0/docs/assets/lodestar-v1.1.0-social.png)

## What changed

- Added deterministic `lodestar start` projections capped at 16 KiB with exact
  follow-up commands when optional context is omitted.
- Added actor-scoped `lodestar work status|start|done|history` records with
  atomic monotonically increasing revisions.
- Added one project handoff lineage with idempotent save, atomic startup claim,
  source-session exclusion, claimant retry safety, and clear.
- Included the Lodestar Codex plugin, which loads startup once and handles the
  exact natural prompt `handoff now` with host authorization, semantic
  validation, and secret redaction.
- Normalized Windows and WSL paths to one project identity and added a WSL shim
  that invokes the one-shot Windows runtime instead of opening the shared
  SQLite file with a second engine.
- Preserved both original direct-content records and wrapped
  `content.value` records through one output adapter.
- Added schema version 3, which keeps only universal record tables. Version-2
  specialized continuity tables are removed only when empty; nonempty state
  halts migration without data loss.
- Restored and expanded the complete regression suite while retiring the old
  service and specialized continuity runtime.
- Rebuilt the GitHub and npm front page around the unified suite.

## Install

Node.js 24.15.0 or newer is required:

```text
npm install --global lodestar-agent-context@1.1.0
lodestar start --cwd .
```

The optional Codex integration is included in the package under
`codex-plugin/` and in the source repository.

## Release verification

The tag workflow runs the complete test suite, package-content checks, packed
executable smokes on Linux, macOS, and Windows, and CodeQL. It publishes the
exact npm tarball with provenance and attaches that tarball, SHA-256 checksums,
and the release artwork to this GitHub release.
