# Lodestar v0.6.0

Lodestar v0.6.0 makes context continuity inspectable and recoverable without
changing the small deterministic retrieval path. New state is sealed,
mutations distinguish pre-commit failure from post-commit durability
uncertainty, snapshots are independently verifiable, and maintenance stays
recoverable.

## Highlights

- New generations include a SHA-256 manifest covering the exact regular-file
  set. `agentctx doctor --deep` verifies completeness, checksums, canonical
  generation identity, and rebuilt deterministic indexes.
- Legacy unsealed generations remain readable and are reported explicitly.
  Integrity detects accidental corruption and inconsistency; it is not a claim
  of authenticity against an attacker who can rewrite the complete store.
- Generation, pointer, audit, initialization, snapshot, and restore writes use
  file synchronization before promotion where the filesystem supports it.
  A directory-sync failure after rename is reported as committed durability
  uncertainty instead of a false unchanged-state error.
- Failed staging removes the full transaction tree when cleanup is available,
  while preserving the original I/O cause if cleanup also fails.
- `snapshot --to`, `snapshot --verify`, and restore-to-new-home provide a
  portable recovery path without overwriting existing state.
- `maintain` previews deep retention, storage, audit, and bounded source-drift
  status. `maintain --apply` moves exact excess generations to recoverable
  quarantine and can rotate a validated audit log with a SHA-256 checkpoint.
- `recover <generation> [--promote]` deeply validates and restores one
  quarantined generation through an audited rollback-capable transaction.
- Portable project shard identities, physical locator confinement,
  race-safe destination claims, bounded archive/index/input processing, and
  complete rotated-audit snapshots close the adversarial release findings.
- Installer, Windows shim, state-home, and Codex adapter changes now share a
  rollback-complete setup boundary with concurrent-edit detection.
- `agentctx --help`, command-specific help, `agentctx --version`, and installer
  help/version provide a complete first-run CLI surface without requiring a
  configured state home.
- Physical locator checks translate cataloged Windows roots under WSL and
  doctor reports one authoritative unhealthy result per locator.
- Record, catalog, graph, shard, and store budgets are enforced before
  persistence. The project limit matches the proven 500-project scale.
- Destructive quarantine purge and a public no-op schema migration command are
  deliberately absent from v0.6.

## Recovery workflow

```sh
agentctx doctor --deep
agentctx snapshot --to /backups/lodestar-v0.6
agentctx snapshot --verify /backups/lodestar-v0.6
agentctx maintain
agentctx maintain --retain 10 --apply
```

Restore only to a new path:

```sh
agentctx restore \
  --from /backups/lodestar-v0.6 \
  --home /path/to/restored-lodestar
agentctx doctor --home /path/to/restored-lodestar --deep
```

## Install

Download `lodestar-agent-context-0.6.0.tgz` and `SHA256SUMS.txt`, verify the
checksum, then install:

```sh
npm install --global ./lodestar-agent-context-0.6.0.tgz
agentctx init
agentctx doctor --deep
```

Native Windows and WSL use the same package and store format. Existing v0.5
state homes remain readable; the next deliberately written generation is
sealed automatically.

## Verification

The release gate covers the complete Node suite, corruption and manifest
omission, pre- and post-commit fault injection, resource boundaries, snapshot
parity, maintenance preview/apply parity, the deterministic retrieval and
500-project performance benchmarks, packed lifecycle execution, and hosted
Windows, Ubuntu, and macOS package smoke checks.

The local release candidate passed 198/198 WSL/Linux tests, 195 native Windows
tests with zero failures and three intentional platform skips, and the complete
isolated packed lifecycle. Publication still requires the exact release commit
to pass hosted Windows, Ubuntu, and macOS before tagging.

The selected product boundary and proof contract are preserved in the
[v0.6 trust-recovery codeplan](../plans/2026-07-30-lodestar-v0.6-trust-recovery-codeplan.md).
