# Lodestar v0.7.0

Lodestar v0.7.0 is the payload-and-payback release. It makes the default agent
hand-off smaller, makes package transitions visible before installation, and
removes operational noise that obscured real failures—all while preserving the
version 1 store, exact retrieval, local-first operation, and zero runtime
dependencies.

## What changed

- Reduced the hard startup response budget from 16 KiB to 5 KiB. Required
  records remain complete; optional context is represented by compact,
  deterministic routing cards and can still be fetched by exact ID.
- Added startup-payload, evidence-transfer, inspected-byte, and elapsed-time
  observations to the paired benchmark without converting them into invented
  token or dollar claims.
- Added installer preflight reporting for installed and target versions,
  package transition, active command path, and PATH shadowing. Accidental
  downgrade and unknown-version replacement now fail closed unless explicitly
  authorized.
- Added package and Node runtime versions to `doctor`.
- Made deep generation inspection bounded-concurrent while preserving
  deterministic issue ordering.
- Stopped treating an unavailable alternate project root as a problem when
  another cataloged root is reachable. A project with no reachable root still
  produces an error or blocker.
- Made generated profiler locators project-relative, existing, and bounded, so
  absent build outputs and incorrectly rebased monorepo entrypoints no longer
  create false health warnings.
- Made standalone profiler `--help` side-effect free, honored standalone
  `--dry-run`, and rejected malformed options instead of silently profiling.
- Made snapshot creation build a missing destination parent after path-overlap
  validation.
- Tightened category scoring for quoted and shell-wrapped commands and taught
  the managed Codex adapter not to re-fetch required records already delivered
  at startup.
- Made tagged release publication wait for pinned CodeQL analysis in the same
  workflow, aligning the public security claim with the actual publish gate.

## Measured payoff

The real 71-project canonical startup packet is **4,879 bytes**, down from
16,300 bytes (**70.1% smaller**), with all six required records preserved.

Fresh deterministic release-candidate runs on Node.js v22.22.3 under WSL
produced:

| Profile | Correct | Files | Bytes inspected | Median time |
| --- | ---: | ---: | ---: | ---: |
| 10 projects | 4/4 → 4/4 | 16 → 6 | 65,536 → 4,943 | 4.404 → 2.840 ms |
| 100 projects | 4/4 → 4/4 | 64 → 6 | 1,048,576 → 24,923 | 15.424 → 10.119 ms |
| 500 projects | 4/4 → 4/4 | 256 → 6 | 8,388,608 → 114,523 | 62.596 → 41.551 ms |

Every profile avoided broad search, returned zero cross-project records, and
stayed within the 5 KiB startup budget. The 100-project profile avoided
1,023,653 inspected bytes while adding 3,234 evidence bytes and saving 5.305
ms at the median. The 500-project profile avoided 8,274,085 inspected bytes and
saved 21.045 ms.

Deep audit of the same 55-generation Windows-backed state home fell from 48.87
seconds to 18.74 seconds after bounded-concurrent inspection (**61.7% faster**).
After verified snapshot, refresh, and recoverable retention maintenance, the
canonical deep audit completed in 3.75 seconds with **zero issues**
(**92.3% faster end to end**).

The deliberately tiny direct-scan controls remain documented losing cases.
Lodestar is not claiming that fixed routing beats every trivial lookup; it pays
for itself where repository ambiguity and inspection volume exceed that fixed
cost.

## Verification

- 203/203 local tests passed with zero failures or skips.
- The canonical 71-project store passed deep doctor with zero errors, warnings,
  or blockers and retained one active sealed generation.
- The package contains 74 declared public files, no runtime dependencies, and
  no private state.
- Paired retrieval and all 10/100/500-project performance profiles passed.
- The 48-trial live-agent category plan reproduced deterministically without
  executing a provider or incurring cost.

The release workflow independently reruns the complete suite and packed
lifecycle on Ubuntu, macOS, and Windows, runs CodeQL, builds the package from
the exact tag, publishes `SHA256SUMS.txt`, and attaches artifact provenance
before publishing the GitHub release.

## Honest claim boundary

The deterministic tests prove bounded payload, answer parity on their
registered questions, project isolation, less repository inspection, and
positive elapsed-time payback at normal and stress scale on the measured
machine.

They do not prove universal language-model quality or provider-token savings.
The one authenticated local Codex smoke remains non-publishable because it
inherited user context; it inspected one file instead of six but was slower and
used more reported input tokens. A randomized invocation-isolated provider run
remains future evidence, not a v0.7.0 claim.

## Install

Download `lodestar-agent-context-0.7.0.tgz` and `SHA256SUMS.txt` from the
[v0.7.0 GitHub release](https://github.com/VerbalChainsaw/Lodestar/releases/tag/v0.7.0),
verify the checksum, then install:

```sh
npm install --global ./lodestar-agent-context-0.7.0.tgz
agentctx --version
agentctx doctor --deep
```

The design and claim boundary are recorded in the
[v0.7 payload-and-payback codeplan](../plans/2026-07-30-lodestar-v0.7-payload-payback-codeplan.md).
