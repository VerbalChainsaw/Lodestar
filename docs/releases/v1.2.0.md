# Lodestar 1.2.0

Lodestar 1.2.0 finishes the consolidation 1.1.0 began. Startup context, durable
knowledge, advisory work presence, session continuity, durable decisions, and the
agent skills themselves now live behind one `lodestar` executable, one versioned
JSON envelope, one universal record model, and one SQLite database.

The practical effect is that an agent has one place to ask. Session startup
returns the project, its governing rules, current and superseded decisions,
relevant knowledge, active work, and any eligible handoff in a single bounded
response, instead of the agent reading its way through scattered instruction
files to reconstruct the same state.

![Lodestar 1.2.0](https://raw.githubusercontent.com/VerbalChainsaw/Lodestar/v1.2.0/docs/assets/lodestar-v1.2.0-social.png)

## What changed

- Added `lodestar decision set|drop|show|inject`: append-only decision events
  with a deterministic FACTS/DEAD projection returned at startup, so a superseded
  choice stays visibly dead rather than quietly resurfacing.
- Added `lodestar skills install|sync|verify|remove`, one lifecycle that installs
  and verifies the managed skills and instruction templates across Codex, Claude,
  Hermes, and OpenCode. Every replacement is backed up first and the backup path
  is returned in the response.
- Extended continuity to session-isolated `handoff arm|status|checkpoint|now|
  disarm` with atomic next-session claiming at startup.
- Generated one required governance record and one canonical bootstrap from the
  managed assets, returned on every startup, with explicitly configured client
  bootstrap files managed transactionally alongside the skill payload.
- Imported supported historical knowledge, work, decision, and continuity state
  through one checksummed, backup-first, idempotent manifest.
- Kept WSL skill staging and backups on the Linux filesystem, translated client
  roots at the one-shot shim boundary, and verified the installed shim is
  executable before reporting success.
- Preflighted and staged the complete managed-skill batch before touching any
  client, compensating handled cross-client failures in reverse order.
- Opened the current-schema migration probe read-only and documented the exact
  mutation boundary for startup, migration, state, and skill commands.

## Fixed

- `resolveClientStateHome` recognizes a WSL UNC home before path resolution.
  Because `path.resolve` only treats a backslash as a separator on Windows, the
  previous order turned that path into a relative one on Linux and macOS and lost
  the match.
- The published package no longer carries project-specific instruction templates.
  A release check now reads the built tarball and fails on any absolute home path
  or non-generic template, so local machine detail cannot reach the artifact.

## Install

Node.js 24.15.0 or newer is required:

```text
npm install --global lodestar-agent-context@1.2.0
lodestar start --cwd .
```

The optional Codex integration ships in the package under `codex-plugin/`.

## Upgrading from 1.1.0

The schema is unchanged. Existing registries are read as-is, and `lodestar
doctor` reports schema, integrity, foreign keys, decisions, and continuity health
without writing.

To pick up the managed skills after upgrading:

```text
lodestar skills sync --target all
lodestar skills verify --target all
```

## Release verification

The tag workflow runs the complete suite on Linux, macOS, and Windows, plus
package-content checks, packed-executable smokes, and CodeQL. It publishes the
exact npm tarball with provenance and attaches that tarball, SHA-256 checksums,
and the release artwork to this GitHub release.
