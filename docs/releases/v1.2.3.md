# Lodestar 1.2.3

**One local CLI for agent project state.** This release makes advisory presence work
where it was silently broken, and closes a redaction defect found while proving it.

![Lodestar 1.2.3](https://raw.githubusercontent.com/VerbalChainsaw/Lodestar/main/docs/assets/lodestar-v1.2.3-social.png)

```text
npm install --global lodestar-agent-context@1.2.3
lodestar start --cwd .
```

## Work presence was dead in the harness it was built for

A host knows its session id at the hook boundary. When the agent then shells out, that
id is gone — Codex injects `LODESTAR_AGENT` and `LODESTAR_HARNESS` into spawned shells
but no session variable. Every identity-requiring write therefore failed:

```text
lodestar work start "tracing the seam"   →  identity_required
```

Agents behaved correctly and refused to invent an id, which meant advisory presence
simply never happened.

`lodestar_work_start`, `lodestar_work_done`, and `lodestar_work_status` are now bundled
tools carrying the same host attestation continuity already used: session, turn, and cwd,
bound and single-use. Work needs no spoken authorization the way a baton does — marking
what you are working on is not a user decision — but it does need the exact session.

## Concurrent sessions stay distinct

Work records are keyed by actor. Any shell-side attempt to infer the caller captures a
peer's marker, and the next write erases it — two sessions collapse into one record and
one of them disappears. The CLI now refuses without an explicit `--session` instead of
guessing.

Verified with two concurrent sessions in one project:

```text
A wrote as: codex:session-A     peers visible: 2
B wrote as: codex:session-B     after A closes its own: 1 open (B survives)
```

## Redaction was corrupting its own output

A secret pattern with no capture group passes the match **offset** as the replacer's
second argument. Treating that number as a prefix wrote it into the text:

```text
before:  key is ghp_...   →   key is 9[REDACTED]
after:   key is ghp_...   →   key is [REDACTED]
```

Assignments still keep their prefix (`API_KEY=[REDACTED]`), which is why the bug hid:
the capture-group case looked right.

## Also fixed

- The Codex plugin derives its version from its own manifest rather than a literal. A
  build had been running 1.1.0 against a 1.2.2 registry while reporting 1.1.0 over MCP.
- Skill and README guidance now points at the tools, so an agent is not sent down the
  shell path that requires a session it cannot supply.

## Verified

- 157 tests on Windows and native Linux; Linux, macOS, and Windows in CI.
- Two concurrent sessions in one project keep separate identities, and closing one does
  not close the other.
- A work attestation cannot be replayed, and cannot be reused to authorize a baton.
- Continuity still refuses any session it cannot verify.

## Upgrading

Schema unchanged since 1.2.0.

```text
npm install --global lodestar-agent-context@1.2.3
lodestar doctor
lodestar skills sync --target all
```

Requires Node.js 24.15.0 or newer.
