# Lodestar 1.2.2

**One local CLI for agent project state.** This release makes the thing that
keeps a registry useful — knowing what belongs in startup and what does not — a
property of the tool instead of a matter of discipline.

![Lodestar 1.2.2](https://raw.githubusercontent.com/VerbalChainsaw/Lodestar/main/docs/assets/lodestar-v1.2.2-social.png)

```text
npm install --global lodestar-agent-context@1.2.2
lodestar start --cwd .
```

## Why this release exists

Startup is a fixed 16 KiB budget, not a growing list. Measured on a real registry
before this work, required records consumed **15,187 of 16,384 bytes — 530 bytes
of headroom**. That puts "record more" and "startup stays useful" in direct
opposition, which is the actual reason knowledge stores go stale. Nobody decides
to stop curating; the budget quietly runs out and the tool starts shedding.

So capture and injection are now separate operations.

## Capture is free

`lodestar pending list|add|promote|drop` writes candidates into a scope that
`start` never selects. Three captures leave `required` and `context` byte-for-byte
identical and grow the payload by under 32 bytes — the integer count.

An agent records a candidate by writing a line beginning `LODESTAR NOTE:` in its
final message; the existing `Stop` hook harvests it. A marker is deterministic: it
never fires on an ordinary message, needs no extra model call, and cannot fill the
queue with near-misses. Capped at three per turn and deduplicated by source.

Promotion moves a candidate into project scope and **never marks it required**, so
accepting knowledge cannot silently tax every future session.

## The budget is now observable, and its failure is recoverable

`doctor.checks.startup_budget` reports the standing cost of global required
records — charged to every project on the machine — measured on the bytes `start`
actually serializes, including the injected governance record. It raises
`startup_budget_low` while there is still room to act.

Previously, exceeding the budget failed `start` outright. Since `start` is the
first command of every session, that stopped all work, and the error did not say
which record to shrink. It now names the largest required records with their sizes
and the exact command to fix one:

```json
"largest_required": [
  { "id": "g:example", "scope": "global", "bytes": 3228 }
]
```

## Bounded by design

The review queue is a rolling window of 100 candidates per project, and every
eviction is reported. A queue past a few screens is one nobody triages, so
reaching the cap means review already stopped — keeping the most recent candidates
is more useful than hoarding stale ones.

## Verified

- 152 tests on Windows and native Linux; Linux, macOS, and Windows in CI.
- 12 concurrent writers across three write families: 12/12 succeeded, integrity
  clean, zero foreign-key violations.
- A corrupted database returns a parseable `database_integrity` envelope rather
  than crashing.
- Unicode, emoji, embedded newlines, and at-limit input accepted; oversize input,
  bad identifiers, and out-of-range limits rejected with stable error codes.

## Upgrading

The schema is unchanged from 1.2.0. Existing registries are read as-is.

```text
npm install --global lodestar-agent-context@1.2.2
lodestar doctor
lodestar skills sync --target all
```

Requires Node.js 24.15.0 or newer.
