# Lodestar 3.0.1

Candidate date: 2026-10-14.

**Local candidate.** This patch is prepared for local packaging, installation and
verification. Version 3.0.1 has not been published to npm or GitHub; there is no
3.0.1 download link or registry installation command. The
[published 3.0.0 release](https://github.com/VerbalChainsaw/Lodestar/releases/tag/v3.0.0)
and its [release notes](v3.0.0.md) remain the retained public release.

## What changed

- **JSON value preservation:** explicit `null` stays `null` through record
  creation, reads, replacement, before-image history and exact request replay.
  Lodestar no longer changes that supplied value into `{}`.
- **Bounded pagination:** interface reads limit each raw core page to the
  remaining record budget. Continuations retain the exact core cursor and
  database revision, preventing skipped or repeated records at a client limit.
- **Recovery certainty:** a matching successful core receipt is required before
  reporting that a save committed. Failed or uncertain delivery keeps its
  recovery evidence and unresolved outcome. Receipt instructions are offered
  only when the context can form a usable exact-request recovery command.
- **Recovery capture:** Manager accepts a reused producer context only after
  complete configuration and request checks, including the configuration path.
  Incomplete older context remains evidence and receives a fresh capture rather
  than bypassing the recovery journal.
- **Native recovery compatibility:** Loader dispatch bindings retain their exact
  serialized values, so Unicode and escaped characters in project paths do not
  cause the core to reject a valid save. Existing native journals remain readable.
- **Runtime source identity:** the configured CLI file's bytes participate in
  source identity even when its filename differs from `lodestar.mjs`. A changed
  selected executable invalidates the prior runtime identity before saving.
- **Same-project checkout rebind:** an ordinary record can be explicitly rebound
  from checkout A to an accessible checkout B in the same canonical project.
  The write must carry the current basis and project mapping closure; changing
  checkout applicability preserves the record ID, content, associations,
  before-image history and exact replay. It does not relocate sources or change
  their recorded observations. Reinspect checkout-relative evidence at B. See
  the [schema procedure](../schema.md) and [operator recipes](../operator-recipes.md).
- **Bounded compatibility skill:** the packaged Adderall skill routes substantive
  project work through the applicable project guidance and installed Lodestar.
  It removes obsolete dose/roleplay and automatic overengineering instructions
  while retaining a bounded task-focus workflow.

The separate review-helper repair from the robustness scan belongs to its own
maintained tool; it is not a new Lodestar runtime feature.

## Compatibility and local installation

Contract 5 and schema 5 remain unchanged. Existing schema-5 databases need no
migration, and the patch adds no runtime dependency or second store. Schema-4
conversion still requires the explicit verified upgrade procedure.

The CLI requires **Node.js 24.15.0 or newer**. Loader and Manager additionally
require **.NET 10 Desktop Runtime (x64)** and **PowerShell 7**. Verify the exact
local tarball and Windows ZIP against the candidate delivery's SHA-256 inventory.
Replace the placeholder below with the verified tarball's absolute path:

```text
npm install --global --ignore-scripts "<candidate-directory>/lodestar-agent-context-3.0.1.tgz"
lodestar setup --target all
lodestar setup --target all --apply
lodestar skills verify --target all
lodestar doctor
lodestar start --cwd .
```

Inspect the setup plan before applying it. Choose individual targets if needed.
An existing store does not need `init`; use it explicitly only when creating a
new store. The local Windows artifact is `Lodestar-3.0.1-win-x64.zip`; extract
the complete archive and use `Install.cmd` or the documented portable setup.
Keep the selected database external and preserve `interfaces.json` during updates.

See [installation](../installation.md#local-301-candidate) for isolated CLI and
local Codex marketplace paths. Native skill installation, host activation,
package tests and extracted Windows checks establish different evidence; the
candidate delivery report records which checks actually ran. Publication and
public landing-page deployment remain outside this local patch delivery.
