# Lodestar v0.5.0

Lodestar v0.5.0 makes the public context store capable of replacing a separate
project list without becoming a project-management database. It consolidates
bounded project facts into the same deterministic linked store agents already
use, while keeping startup small and repository source authoritative.

## Highlights

- `migrate-projects` now previews and merges into populated Lodestar stores.
  It preserves stable project IDs, curated records, generated profiles, and
  projects absent from the incoming registry.
- Repeat imports are idempotent. Unchanged input creates no new generation and
  no audit event.
- Project descriptions, activity, commands, entrypoints, endpoints, and memory
  anchors are retained in linked portfolio records. Startup receives one
  compact portfolio card; detailed facts remain exact-retrieval payloads.
- Ambiguous identity matches and unknown source fields fail closed with
  actionable structured errors.
- `coverage` now distinguishes `ready`, `incomplete`, `stale`, and `blocked`
  projects. `--max-age-days` controls generated/imported freshness and
  `--require-ready` provides a nonzero automation gate.
- `doctor` identifies incomplete, stale, and unverified project context without
  confusing maintenance warnings with structural store corruption.
- The store remains zero-dependency JSON/JSONL with immutable generations,
  deterministic sidecar indexes, no daemon, no database, and no repository
  content ingestion.

## Consolidate a project registry

Always preview the first merge:

```powershell
agentctx migrate-projects `
  --from C:\path\to\projects.json `
  --home C:\Users\name\.lodestar `
  --dry-run
```

```sh
agentctx migrate-projects \
  --from /path/to/projects.json \
  --home /path/to/.lodestar \
  --dry-run
```

Review the `added`, `updated`, `unchanged`, `removed`, and per-project actions.
Then rerun without `--dry-run`. The external registry remains untouched.

The supported bounded fields are project identity and roots, aliases, stack,
description, lifecycle status, activity summary, Git-repository status, test,
build and typecheck commands, entrypoints, endpoints, and memory anchors.
Unknown fields are rejected rather than silently lost.

`--force` retains the older deliberate full-catalog replacement behavior. It is
not needed for normal consolidation.

## Establish readiness

Registry facts provide useful width; bounded profiling supplies repository
starting knowledge:

```sh
agentctx profile-projects --home /path/to/.lodestar
agentctx coverage --home /path/to/.lodestar
agentctx coverage --home /path/to/.lodestar --require-ready
agentctx doctor --home /path/to/.lodestar
```

The readiness gate covers project identity, commands, architecture,
entrypoints, environment, rules, hazards, decisions, memory, and common
answers. Curated records are durable. Generated and imported records must have
a valid verification timestamp within the configured age.

## Install

Download `lodestar-agent-context-0.5.0.tgz` and `SHA256SUMS.txt` from this
release, verify the checksum, and install:

```powershell
npm install --global .\lodestar-agent-context-0.5.0.tgz
agentctx init
agentctx doctor
```

```sh
npm install --global ./lodestar-agent-context-0.5.0.tgz
agentctx init
agentctx doctor
```

Native Windows and WSL use the same package and store format. For a shared
state home, use `C:\Users\name\.lodestar` on Windows and
`/mnt/c/Users/name/.lodestar` under WSL.

## Verification

This release is gated by the complete Node test suite, real 67-project registry
preview, stable-ID/idempotence and preservation tests, deterministic
material-lift fixtures, operation and scale performance benchmarks, package
content checks, isolated tarball installation, and native Windows plus WSL
execution.
