# Lodestar 1.2.4

A resumed session could not read its own baton. This release fixes that and hardens
the hook against taking a session down with it.

![Lodestar 1.2.4](https://raw.githubusercontent.com/VerbalChainsaw/Lodestar/main/docs/assets/lodestar-v1.2.4-social.png)

```text
npm install --global lodestar-agent-context@1.2.4
lodestar start --cwd .
```

## Reading the baton no longer needs a spoken phrase

Checking continuity is the first thing an agent does when resuming work. But
`lodestar_handoff_status` required the exact spoken authorization phrase, and a
resumed session has no phrase to point at. The call was denied, and the only signal
that reached the agent was:

```text
Mcp error: -32000: Missing host attestation
```

The agent then spent a dozen commands reading `continuity.mjs` and `continuity.test.mjs`
trying to work out why a read was refused.

`handoff status` mutates nothing — it opens no transaction and takes no options. It is
now attested directly, still bound to this session, turn, and cwd. Every command that
writes a lane keeps the exact-phrase requirement:

```text
handoff_status      allow + attestation
handoff_now         deny
handoff_arm         deny
handoff_checkpoint  deny
handoff_disarm      deny
```

## The hook fails closed

Issuing an attestation writes to the plugin data directory. If that write failed, the
hook threw and took the host session with it. It now denies the command and explains
why, which is the correct outcome for a guard that cannot record its own decision.

## Upgrading

Schema unchanged since 1.2.0. Refresh the Codex plugin so the fix reaches the host:

```text
npm install --global lodestar-agent-context@1.2.4
codex plugin add lodestar@personal
lodestar skills sync --target all
```

Requires Node.js 24.15.0 or newer.
