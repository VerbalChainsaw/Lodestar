# Lodestar 1.5.0

Package: `lodestar-agent-context@1.5.0`.

## The boundary tightened

Lodestar no longer owns external skill directories or repository agent files.
`lodestar skills` is read-only verification — `install`, `sync`, migration,
replacement, and removal are gone — and `lodestar agents` is read-only status,
verification, and template output. The npm package still ships the complete
managed skill set as canonical source; hosts copy, hash, and verify exactly
rather than asking Lodestar to mutate their trees.

## No startup cap of its own

Lodestar defines no startup budget. `start` returns all optional context unless
the caller passes an explicit per-call `--startup-budget <positive-safe-integer>`,
which targets optional records only and never sheds required governance,
decisions, or handoff state. The `LODESTAR_STARTUP_BUDGET` environment variable
and `config`-record budget sources were retired. `data.budget` reports the target
in force for that one call and whether it was met; required material remains
complete even when the target is exceeded.

## Decision markers

Current decisions carry an `accepted` or explicit `blocked` status
(`decision set --status blocked`, `decision status <key> accepted|blocked`);
projections render `[DECISION ...]`, `[SUPERSEDED ...]`, and `[DEAD ...]`
markers, and every dead item renders its negation sentence — `<old> is DEAD; do
not propose, use, or restore it. Use <current>. Reason: ...` — so a kill is
unmissable and cannot silently resurface. Kill authority is enforced: direct
CLI writes are Director-issued and stay closed to revival; hook-captured markers
are agent-issued and reopen by evidence.

## One marker grammar

Projection and capture share one quote-aware grammar (`src/markers.mjs`). A
malformed or truncated marker is skipped, never allowed to suppress later
markers. Notes use the canonical `[NOTE text="..."]` marker; the historical
`LODESTAR NOTE:` line is still tolerated by capture.

Requires Node.js 24.15.0 or newer.
