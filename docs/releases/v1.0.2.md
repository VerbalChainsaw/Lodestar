# Lodestar 1.0.2

Lodestar 1.0.2 improves the project front page and release materials for the
1.0 architecture.

The runtime remains the same small, zero-dependency local registry shipped in
1.0.1: one `lodestar` executable, one SQLite database, deterministic JSON, and
no required setup command. This patch improves how that product is presented
and released without expanding the core.

![Lodestar launch hero](https://raw.githubusercontent.com/VerbalChainsaw/Lodestar/v1.0.2/docs/assets/lodestar-launch-hero.png)

## What changed

- A new GitHub and npm front page explains the product, its boundaries, and
  the zero-touch first write near the top.
- Original hero and square announcement graphics are part of the tagged source
  and attached to this GitHub release.
- Reusable launch copy is available in the
  [announcement](https://github.com/VerbalChainsaw/Lodestar/blob/v1.0.2/docs/announcements/lodestar-v1.0.2.md).
- npm metadata now describes the package more clearly and makes the local,
  offline, JSON-first use case easier to discover.

No command, schema, database behavior, migration behavior, dependency, or
executable changed from 1.0.1.

## Install

Node.js 24.15.0 or newer is required:

```text
npm install --global lodestar-agent-context@1.0.2
```

There is no mandatory initialization step. The first structurally valid
`lodestar put` creates the registry automatically. `lodestar init` remains an
optional way to create an empty registry or retrieve the bootstrap contract.

## What Lodestar is

Lodestar stores compact, structured project knowledge and retrieves it through
stable IDs, exact aliases, bounded search, and explicit links. It keeps known,
known-empty, unavailable, unknown, and stale states distinct.

It does not scan repositories, infer completeness, orchestrate agents, run a
service, contact providers, or promise universal accuracy or token savings.
When context is missing, callers inspect the repository normally.

## Release verification

The tag workflow must pass the complete test suite, package-content checks,
packed-executable smoke tests on Linux, macOS, and Windows, and CodeQL before
publishing. It then publishes the exact tarball to npm with provenance,
attests the same artifact on GitHub, and attaches checksums plus both launch
graphics to this release.
