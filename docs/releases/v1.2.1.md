# Lodestar 1.2.1

**One local CLI that answers "what is this project, what was decided, what is in
flight, and where did the last session leave off" — in a single call.**

![Lodestar 1.2.1](https://raw.githubusercontent.com/VerbalChainsaw/Lodestar/v1.2.1/docs/assets/lodestar-v1.2.1-social.png)

```text
npm install --global lodestar-agent-context@1.2.1
lodestar start --cwd .
```

## Why use it

An agent starting work on a repository reconstructs the same context every time:
read the instruction file, read the README, chase whatever those reference, guess
at what was already decided. That is slow, it is inconsistent between sessions,
and it silently resurfaces decisions that were reversed months ago.

Lodestar answers all of it in one bounded call. Measured on this repository with
a populated registry:

| | Lodestar | Reading the docs |
| --- | --- | --- |
| Calls | 1 | one per file |
| Bytes returned | **5,872** | 28,456 |
| Wall clock | **155 ms** | file reads + model time |

You get the project identity, its governing rules, current and superseded
decisions, relevant knowledge, who else is working, and any handoff waiting for
this session — as JSON, bounded to 16 KiB, with exact follow-up commands when
something was omitted.

Other properties that matter in practice:

- **Zero dependencies.** Node's built-in SQLite, nothing else. 66 files.
- **One registry.** Windows and WSL reach the same database through a one-shot
  shim; there is no second engine and no background daemon.
- **JSON by default.** `--human` when a person is reading. Errors are the same
  envelope on stderr, so failures parse as reliably as successes.
- **Local only.** No network dependency, no telemetry, no service to run.

## What's in 1.2

**Durable decisions.** `lodestar decision set|drop|show|inject` records decisions
as append-only events and projects them into FACTS and DEAD at startup. A choice
that was reversed stays visibly dead instead of quietly coming back.

**Managed skills.** `lodestar skills install|sync|verify|remove` is one lifecycle
for the bundled skills and instruction templates across Codex, Claude, Hermes,
and OpenCode. Every replacement is staged, backed up, and the backup path is
returned in the response.

**Session continuity.** `lodestar handoff arm|status|checkpoint|now|disarm` with
session isolation and atomic next-session claiming at startup, so exactly one
successor picks up a baton.

**Always-on governance.** One required rule record and one canonical bootstrap,
generated from the managed assets and returned on every startup.

**One import path.** Historical knowledge, work, decision, and continuity state
import through a single checksummed, backup-first, idempotent manifest.

## Fixed since 1.2.0

- **Cross-platform project matching.** Stored project roots are now matched
  through `realpath`. The cwd was already resolved, so a project behind a symlink
  never matched — macOS resolves `/var` to `/private/var`, Windows expands 8.3
  short names and junctions.
- **Package hygiene.** Three project-specific instruction templates and the
  reference table that listed them are out of the published package. A release
  check now reads the built artifact and fails on an absolute home path, a
  non-generic template, or a doc citing a template that does not ship.
- **Reproducible builds.** The managed-asset parity lock compares content rather
  than raw bytes, so it holds on a fresh clone regardless of how the checkout
  handles line endings.

## Upgrading

From any 1.x. The schema and CLI surface are unchanged from 1.2.0, and existing
registries are read as-is.

```text
npm install --global lodestar-agent-context@1.2.1
lodestar doctor
lodestar skills sync --target all
lodestar skills verify --target all
```

`doctor` reports schema, integrity, foreign keys, decisions, and continuity
health without writing.
