# Lodestar 1.4.2

Lodestar clients now share one startup policy. Adapters do not invent narrower caps.

## Constraint provenance

The Director Golden Operating Rules now require every cap, truncation, omission,
client-specific policy, provider-specific policy, behavioral restriction, or governance
layer to name a proven requirement and its authoritative owning boundary. A component's
own constant, test, comment, or documentation cannot prove its necessity.

Required authority and mutation data may never be silently truncated or treated as
complete. Optional context may be omitted only when the omission is explicit, exact,
addressable, and recoverable.

## One startup resolver

The Codex adapter no longer passes a private `--startup-budget` value or declares its own
context limit. It calls the same `lodestar start` as every other client. Lodestar defines
no startup budget of its own: `start` returns all optional context unless the caller
explicitly passes `--startup-budget <positive-safe-integer>`, which targets optional
records only and never sheds required governance, decisions, or handoff state.

Startup injection now includes a closing completeness marker. If a host ever cuts the
payload at an undocumented boundary, the missing marker tells the agent to stop before
mutation rather than operate on partial authority.

Requires Node.js 24.15.0 or newer.
